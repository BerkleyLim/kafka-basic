# 01. 개념

## 1. Kafka 는 무엇인가

**순서대로 쌓이는 로그(append-only log)를 여러 서버에 나눠 저장하고, 여러 소비자가 각자 읽은 위치를 기억하며 읽어 가는 시스템**이다.

메시지 큐와 다른 점은 **읽어도 지워지지 않는다**는 것. 보관 기간(기본 7일)이 지나야 지워진다.
그래서 같은 메시지를 서로 다른 시스템(저장 · 알림 · 통계)이 각자 따로 읽을 수 있다.

## 2. 용어

| 용어 | 뜻 | 이 저장소에서 |
|---|---|---|
| **Broker** | Kafka 서버 한 대 | docker-compose 의 `kafka` 1대 |
| **Topic** | 메시지를 담는 이름 붙은 로그 | `device-events`, `device-events.DLT` |
| **Partition** | 토픽을 쪼갠 조각. **순서는 파티션 안에서만** 보장 | `device-events` 는 3개 |
| **Offset** | 파티션 안에서 메시지의 번호 (0, 1, 2 …) | 파티션마다 따로 센다 |
| **Key** | 어느 파티션에 넣을지 정하는 값. 같은 키 → 같은 파티션 | `deviceId` |
| **Producer** | 보내는 쪽 | Step 02 |
| **Consumer** | 읽는 쪽. 스스로 당겨 온다(pull) | Step 03 |
| **Consumer Group** | 같은 이름의 소비자 묶음. 파티션을 **나눠** 읽는다 | Step 04 |
| **Committed offset** | 그룹이 "여기까지 읽었다" 고 적어 둔 위치 | `__consumer_offsets` 토픽에 저장 |
| **Replica / ISR** | 파티션 복제본 / 리더를 잘 따라오는 복제본 | 브로커 1대라 1 |
| **KRaft** | ZooKeeper 없이 Kafka 스스로 메타데이터를 관리하는 방식 (4.0 부터 이것만) | `KAFKA_PROCESS_ROLES: broker,controller` |

## 3. 파티션과 순서

```
key=device-A ──hash──▶ partition 0 : [A1][B1][A2][B2][A3]…
key=device-C ──hash──▶ partition 1 : [C1][C2][C3]…
                       partition 2 : (비어 있을 수도 있다)
```

- 같은 설비의 이벤트는 순서가 지켜진다. **다른 설비끼리의 순서는 보장되지 않는다.**
- 키 3개를 파티션 3개에 해시로 나누면 고르게 갈 거라고 생각하기 쉽지만 아니다. 위처럼 한 파티션에 몰릴 수 있다 (Step 02 실행 결과에서 실제로 본다).
- 키 없이 보내면 프로듀서가 알아서 흩뿌린다 → 순서 보장 없음.

## 4. 소비자 그룹

- 한 파티션은 그룹 안에서 **한 소비자만** 읽는다. → 파티션 수 = 병렬 처리 상한.
- **그룹이 다르면 서로 상관없다.** 같은 메시지를 각 그룹이 모두 받는다.
- 소비자가 들어오고 나갈 때 파티션을 다시 나누는 일을 **리밸런스**라고 한다.

## 5. offset 커밋

커밋 값은 "**다음에 읽을** offset" 이다. offset 5 까지 처리했으면 6 을 커밋한다.

| 언제 커밋? | 결과 |
|---|---|
| 처리 **전** | 처리 중 죽으면 그 메시지는 **유실** (at-most-once) |
| 처리 **후** | 커밋 전에 죽으면 **다시 받는다** (at-least-once) ← 보통 이쪽 + 멱등 처리 |

## 6. 보관

메시지는 소비 여부와 상관없이 `retention.ms`(기본 7일) 또는 `retention.bytes` 가 지나야 지워진다.
그래서 그룹 이름만 바꾸면 처음부터 다시 읽을 수 있다 (Step 03).

## 7. 리스너와 advertised.listeners — 가장 흔한 접속 문제

클라이언트는 처음 붙은 주소(bootstrap)에서 **"앞으로는 이 주소로 오라"(advertised.listeners)** 는 답을 받고, 그 주소로 다시 붙는다.
이 값이 클라이언트 쪽에서 닿지 않는 주소면 **첫 연결은 되는데 그 뒤로 안 된다.**

이 저장소의 docker-compose 는 리스너가 둘이다.

| 리스너 | 알려 주는 주소 | 누가 쓰나 |
|---|---|---|
| `PLAINTEXT_HOST` | `localhost:${KAFKA_PORT}` | 내 PC 의 Java 예제 |
| `PLAINTEXT` | `kafka:19092` | 컨테이너 안 (콘솔 도구 · 웹 UI) |

실제로 겪은 예: `KAFKA_PORT=9192` 로 띄운 뒤 컨테이너 안에서 `--bootstrap-server localhost:9092` 로 붙었더니,
브로커가 `localhost:9192` 로 오라고 알려 줬고 컨테이너 안에는 그 포트가 없어서 `Connection to node 1 could not be established` 가 반복됐다.
→ 컨테이너 안에서는 `kafka:19092` 를 쓴다.
